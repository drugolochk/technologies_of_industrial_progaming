## Практическая работа № 1

**Тема:** подготовка окружения и первые программы на JavaScript.

### Что сделано

1. **Node.js, npm, Git и запуск JS в двух средах.** Файл `practice-01/js/hello.js` пишет имя, группу, номер работы и `typeof document`. Повторный запуск `node practice-01/js/hello.js` дал последнюю строку `Тип document: undefined`. В браузере тот же файл через `index.html` должен дать `object`, потому что там есть DOM, а в Node.js глобального `document` нет. На страницу текст не выводится: используется только `console.log`.

2. **Типы и преобразования.** `js/types.js` считает десять выражений: `"8" + 2` → строка `82`, `"8" - 2` → число `6`, `Number("8") + 2` → `10`, `"12" > "3"` → `false`, `12 === "12"` → `false`, `Number("")` → `0`, `Number("text")` → `NaN`, `Boolean("false")` → `true`, `typeof null` → `"object"`, `typeof NaN` → `"number"`.

3. **Сводка и план.** В `js/progress.js` и `js/plan.js` стоят данные варианта: `totalTasks = 18`, `completedTasks = 6`, `dailyLimit = 5`. Проверки идут до арифметики: `typeof`, `Number.isFinite`, `Number.isInteger`, границы 0…1000, `completedTasks <= totalTasks`.

4. **Отладка `debug.js`.** В файле уже исправленный вариант: `Number(completedText) + Number(additionalText)` и цикл `taskNumber <= 4`. Исходная ошибка (сложение строк `"3" + "2"` → `"32"` и условие `taskNumber < 4`) описана в `practice-01/README.md`, в текущем файле её нет.

5. **Дополнительное задание, вариант Б.** `js/plan-week.js`: первый день — понедельник, суббота и воскресенье без нормы, выходные после последней задачи не добавляются (`while (remainingTasks > 0)`).

`hello.js` в Node.js:

`progress.js`: осталось 12, прогресс `33.3%`, статус «В работе».

`plan-week.js` на данных варианта: **3 рабочих и 3 календарных дня** (пн–ср, норма 5 закрывает остаток 12 до выходных).

### Вывод

Цикл работы соблюдён: один файл запускается в Node.js, граничные случаи отсекаются до расчёта, ошибка сложения строк устранена явным `Number()`, результат зафиксирован в файлах практики. `Number.isFinite` / `Number.isInteger` нужны, потому что `typeof NaN === "number"`.

## Практическая работа № 3

**Тема:** работа с DOM и событиями.

### Что сделано

Интерфейс в `practice-03`: список, фильтры, переключение статуса, удаление. Разметка `index.html` без `onclick` / `onchange`. Подписки один раз в `src/main.js`:

- `listElement.addEventListener("click", handleTaskListClick)`
- `filtersElement.addEventListener("click", handleFilterClick)`
- фильтр приоритета — отдельный слушатель на контейнере

Идентификатор и действие читаются из `dataset` кнопки и карточки (`data-action`, `data-task-id`), клик по вложенному `span` доходит до контейнера за счёт всплытия.

Фильтр хранится в переменных интерфейса. `getVisibleTasks` только отбирает, что показать; `currentTasks` от фильтра не меняется. После изменения модели вызывается `renderApp()` — одна точка перерисовки списка, сводки и пустого состояния.

Сервис задач перенесён из ПР2 (`src/task-service.js`). Набор страницы: без параметра — общий, `?dataset=variant` — вариант 6.

```text
npm start
```

Адреса: `http://127.0.0.1:5503/` и `http://127.0.0.1:5503/index.html?dataset=variant`. Браузерные проверки: `checks.html`.

## Практическая работа № 4

**Тема:** формы, валидация и локальное хранение данных.

### Что сделано

Одна форма на создание и редактирование (`#task-form` в `practice-04`). Режим переключается в `src/main.js` (заголовок, подпись кнопки, поле id).

Три уровня проверки:

1. Ограничения полей в HTML.
2. `validateTaskDraft` в `src/form-validation.js` — нормализация черновика и сообщения у полей.
3. Правила сервиса (`addTask`, `updateTask`, `setTaskCompleted`, `removeTask`) по-прежнему возвращают `{ ok: false, error }`.

Хранение: `src/task-storage.js`. В `localStorage` пишется оболочка `{ version: 1, tasks }`. Успешный `JSON.parse` недостаточен: сверяются версия и схема списка. Повреждённая запись даёт исходный набор, исключение `getItem` / `setItem` / `removeItem` наружу не летит, функция возвращает `{ ok: false, error }`.

Ключи не общие (`src/main.js`):

- `tip-js-practice-04:demo`
- `tip-js-practice-04:variant`
- в режиме проверок — `tip-js-practice-04:checks:demo` или `...:checks:variant`

Сброс вызывает `removeItem` только текущего ключа, не `localStorage.clear()`.

Набор данных тот же, что в ПР2–ПР3. В сервис добавлен `updateTask`.

### Запуск

```text
cd practice-04
npm start
```

Адреса: `http://127.0.0.1:5504/` и `http://127.0.0.1:5504/index.html?dataset=variant`. Другой порт — другой origin и другое хранилище.

`checks/modules.checks.js`: **27 пройдено, 0 не пройдено** (форма, схема, чтение/запись, сброс ключа).
