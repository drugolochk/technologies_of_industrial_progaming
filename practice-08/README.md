## 2. Хук

`useTaskData` синхронизирует React с HTTP. Зависимости эффекта: `api`, поля фильтров и `revision`. Cleanup помечает запрос неактуальным и вызывает `abort`. Мутация блокируется `useRef` до `await`. Успех записи увеличивает `revision`; ошибка GET после POST не отменяет факт создания.

## 6. Контрольные вопросы

1. Запрос в теле компонента запускался бы на каждый рендер.
2. Cleanup — перед новым эффектом и при размонтировании.
3. Callback эффекта должен вернуть cleanup, а не Promise.
4. `snapshot` — результат загрузки, иначе цикл.
5. Новый объект api каждый рендер бесконечно перезапускает эффект.
6. Реализация API может проигнорировать AbortSignal.
7. Иначе ошибка отмены всплывёт после нового фильтра.
8. StrictMode ловит отсутствие очистки.
9. Два синхронных клика видят одно и то же state.
10. `true` означает подтверждённую запись, даже если GET потом упал.
11. Повтор POST может создать дубликат.
12. Общий контроллер сорвал бы сохранение при смене фильтра.
13. Сервер мог уже выполнить операцию.
14. `meta.total` — размер текущей выборки.
15. CORS, внешний вид формы и Network jsdom не проверяет.

## Совместимость со сквозным проектом

Папки ПР7–ПР9 называются `practice-07`, `practice-08`, `practice-09`, как остальные практики.
ПР7 работает с состоянием в памяти страницы. ПР8 добавляет HTTP и общий интерфейс
`{ tasks, categories, meta }` для React-компонентов.

`getTasks` принимает оба формата ответа: массив из ПР9 для КР3 и `{ data, meta }`
из учебного API ПР6/ПР8 и следующих серверных этапов. В случае массива `meta.total`
вычисляется по длине полученной выборки. В обоих случаях проверяются поля задач и
уникальность id; для ответа с `meta` сохраняется проверка `meta.total`.

Для проверки ПР9: в одном терминале `cd practice-09` и `npm start`, в другом —
`cd practice-08` и `npm run dev`. Учебный `npm run api` из ПР8 одновременно не
запускать: серверы используют один порт 5505. С ПР9 работают чтение и создание;
переключение статуса, удаление и сброс демоданных появляются на этапе ПР10.
Для полного CRUD вместо сервера ПР9 запускается `npm start` из `practice-10`.

Проверка переходов ПР8 → ПР9 и ПР8 → ПР10: `npm run check:compatibility` из
`practice-08`. Диагностический `console.log` в `useTaskData` оставлен для КР3;
повторные строки при StrictMode ожидаемы и не меняют состояние приложения.
